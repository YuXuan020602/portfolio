第 8 章 Route Guidance（路线引导）深度解析

拆解苹果 CarPlay 附录（iAP2）中，iPhone 如何把转向引导数据下发给车机，以及工程实现时必须踩准的硬指标。

这份文档是苹果《配件接口规范 · CarPlay 附录》（iAP2 协议的 CarPlay 补充规范）R11 开发者预览版。第 8 章定义了 iPhone 导航（Apple Maps / CarPlay 中的第三方导航 App）如何把"转向引导数据"下发给车机（配件 / Accessory），让车机用自己的导航渲染能力（中控屏、仪表、HUD）显示苹果下发的引导信息。

一句话概括：CarPlay 投屏显示之外，车机若想用自己的 UI 呈现 CarPlay 导航的转向提示，必须走本章的 iAP2 消息通道。

一、本章在文档中的定位

路线引导功能使设备（iPhone）能够向配件（车机）提供转向引导（turn-by-turn）及路线引导元数据。如果配件使用其内置导航系统提供的元数据来呈现导航指令（在中控主屏、仪表盘或抬头显示器上），那么它也必须使用 CarPlay 提供的元数据做同样的呈现。

二、核心机制解析

1. 强制性要求（8.1）

支持 Route Guidance 的车机必须实现 5 条 iAP2 控制会话消息：

消息方向作用
StartRouteGuidanceUpdates车机 → iPhone订阅 / 开启引导数据流
RouteGuidanceUpdateiPhone → 车机引导总状态更新（状态、ETA、距离等）
RouteGuidanceManeuverInformationiPhone → 车机单个"机动动作"（转向）详细信息
StopRouteGuidanceUpdates车机 → iPhone停止订阅
LaneGuidanceInformationiPhone → 车机车道级引导信息

2. 身份识别与显示区域声明（8.2 前半）

  • 车机必须先自我识别：通过 RouteGuidanceDisplayComponent 参数组（Table 17-50）逐个声明每一个显示引导数据的区域（中控主屏、仪表、HUD 各算一个），每个区域要报告可容纳的最大字符数，iPhone 据此优化路名等文本的排版。
  • 若 iPhone 不支持这些消息，会拒绝所有包含这些消息的识别请求——即这是能力协商的一部分。

3. 数据流时序

车机声明 DisplayComponents → 发 StartRouteGuidanceUpdates
    （携带 MaxGuidanceManeuverStorageCapacity / MaxLaneGuidanceStorageCapacity，
      即车机最多能缓存几条机动/车道信息）
→ iPhone 为每个 DisplayComponent 各发一条初始 RouteGuidanceUpdate（全量）
→ iPhone 按容量上限发送若干条 ManeuverInformation 和 LaneGuidanceInformation（初始全量）
→ 行进过程中：增量更新 + 接近路口时的 "diff" 动态更新
→ 结束时 RouteGuidanceState = NoRouteSet

4. 关键状态机与强制行为（8.2 后半，工程实现重点）

要求说明
初始状态收到第一条 RouteGuidanceUpdate 前，必须假定 No Route Set
缓存清理收到 RouteGuidanceState = NoRouteSet 时，必须清空所有缓存的机动信息
400ms 呈现时限RouteGuidanceUpdate 或 ManeuverInformation 的内容必须在 400ms 内呈现给用户——本章最硬的实时性指标，也是认证测试项
ETA 时区显示预计到达时间必须加上 DestinationTimeZoneOffsetMinutes（跨时区场景）；老设备兼容时退回用 TimeZoneOffsetMinutes（DeviceTimeUpdate）
状态判断CarPlay 里的导航 App 不一定支持 iAP2 Route Guidance，车机逻辑必须用 RouteGuidanceState + SourceSupportsRouteGuidance 参数判断何时展示
数据安全红线禁止把路线引导信息发往外部（包括远程服务器），禁止持久化存储，只能用于"向用户显示"和"电动车充电准备"两个用途

5. 走错路的处理（重路由机制）

车机可以丢弃所有索引小于当前索引集（RouteGuidanceManeuverCurrentList）的机动消息。司机走错时，iPhone 有两种恢复方式：

  1. 用新路线覆写后续索引的机动消息；或
  2. 从下一个可用索引开始发送新消息，随后发一条 RouteGuidanceUpdate 指定新的当前索引。

6. 机动状态机（8.3.3 示例）

接近路口时，Maneuver 状态按固定节奏流转：

Continue → Initial → Prepare → Execute → Continue

ManeuverType 指定动作类型（如右转）；车道引导由 PresentLaneGuidance = TRUE/FALSE 控制显示开关，LaneGuidanceCurrentIndex 指示当前所处车道组。

三、两个示例的工程含义（8.3）

  • 图 8-1 普通路口（三岔 / 斜交路口）：ManeuverType: 1（直行类）、DrivingSide: 0（左侧通行图例）、JunctionType: 0（普通路口），出口角 -58°，两个入口角 28°、70°——角度参数用于车机自绘路口大图（junction view）。
  • 图 8-2 环岛：ManeuverType: 28（环岛类）、JunctionType: 1（环岛），4 个入口角（-89°、-54°、-28°、19°）+ 出口角 64°，描述 5 口环岛的几何形状。
即：iPhone 不下发渲染图，只下发几何参数，路口放大图由车机自行绘制——这就是为什么每个 DisplayComponent 要报字符容量、角度要精确到度。

四、与认证的关系（8.4）

自认证（self-certification）测试程序仅向已获批产品计划（approved product plans）的配件厂商开放。工程上需要重点准备的测试项：400ms 呈现时限、状态机转换正确性、NoRouteSet 时的缓存清空、以及数据不得外传的合规检查。

五、给实施团队的要点清单

  1. 显示组件声明要覆盖所有渲染引导的区域（含 HUD / 仪表），漏报会导致对应区域拿不到适配文本。
  2. 缓存容量参数（MaxGuidanceManeuverStorageCapacity 等）要按车机真实能力申报，报小了丢数据，报大了内存压力。
  3. 400ms 端到端呈现是硬指标，链路设计（iAP2 接收 → 解析 → UI 渲染）要整体预算。
  4. 路线数据严禁出车头单元（TSP 云端、日志上传都算违规），架构设计时就要隔离。

8 路线引导（Route Guidance）

路线引导功能使设备（iPhone）能够向配件（车机）提供转向引导（turn-by-turn）及路线引导元数据。如果配件使用其内置导航系统提供的元数据来呈现导航指令（在中控主屏、仪表盘或抬头显示器上），那么它也必须使用 CarPlay 提供的元数据做同样的呈现。

8.1 要求

所有通过 iAP2 支持路线引导功能的配件，必须能够发送或接收以下 iAP2 控制会话消息：

  • StartRouteGuidanceUpdates（第 258 页）
  • RouteGuidanceUpdate（第 258 页）
  • RouteGuidanceManeuverInformation（第 263 页）
  • StopRouteGuidanceUpdates（第 267 页）
  • LaneGuidanceInformation（第 267 页）

8.2 用法

支持路线引导的配件在发送或接收上述必需消息之前，必须先进行自我识别。如果设备不支持任何路线引导消息，它将拒绝所有包含这些消息的识别请求。

配件必须使用 RouteGuidanceDisplayComponent 对每一个显示路线引导数据的显示区域分别进行识别。参见"表 17-50 RouteGuidanceDisplayComponent 参数组"（第 283 页）。

每个 RouteGuidanceDisplayComponent 映射到车辆中一个显示路线引导数据的区域。每个组件包含该显示区域可容纳的最大字符数，以便文本（路名等）能够被格式化为最适合该显示区域的形式。

配件发给设备的 StartRouteGuidanceUpdates 消息会启动设备生成 RouteGuidanceUpdate 消息。

路线引导开始后，设备会针对每个 RouteGuidanceDisplayComponent 各发送一条 RouteGuidanceUpdate 消息。这些初始消息包含车辆维持路线引导状态所需的全部信息。

设备还会发送多条 RouteGuidanceManeuverInformation 消息和多条 LaneGuidanceInformation 消息。消息数量受配件在 StartRouteGuidanceUpdates 消息中的 MaxGuidanceManeuverStorageCapacity 参数和 MaxLaneGuidanceStorageCapacity 参数所请求的更新数量限制。

此外，当驾驶员接近路口时，设备可以发送 RouteGuidanceManeuverInformation "diff"（差量）更新，以动态刷新显示。

配件可以丢弃所有索引小于当前索引集（RouteGuidanceManeuverCurrentList）的 RouteGuidanceManeuverInformation 消息。例如，如果驾驶员转弯错误，设备可以用新路线更新后续已索引的 RouteGuidanceManeuverInformation 消息，也可以从下一个可用索引开始发送新的 RouteGuidanceManeuverInformation 消息，随后发送一条 RouteGuidanceUpdate 消息并指定一个新的 RouteGuidanceManeuverInformation 消息索引作为当前索引。

配件如果希望停止向驾驶员显示路线引导信息，或无法继续显示时，可以随时发送 StopRouteGuidanceUpdates 消息。

在收到第一条 RouteGuidanceUpdate 消息之前，配件必须假定路线引导状态（RouteGuidanceState）为 No Route Set（未设置路线）。

当收到 RouteGuidanceState 为 No Route Set 的 RouteGuidanceUpdate 消息时，配件必须清除所有已缓存的机动动作信息。

RouteGuidanceUpdate 消息或 RouteGuidanceManeuverInformation 消息中包含的信息必须在 400 毫秒内呈现给用户。

当使用 EstimatedTimeOfArrival（预计到达时间）向用户呈现到达目的地的预计时间时，配件必须加上 DestinationTimeZoneOffsetMinutes（目的地时区偏移分钟数），以确保向用户显示的时间对目的地时区是正确的。为向后兼容较旧的设备，如果 RouteGuidanceUpdate 消息中未提供 DestinationTimeZoneOffsetMinutes，配件必须改为加上 TimeZoneOffsetMinutes（参见《配件接口规范》中的"DeviceTimeUpdate"）。

在 CarPlay 中提供转向引导的应用会设置转向导航应用状态（参见"应用状态"，第 164 页）。CarPlay 中可用的导航应用可能不支持 iAP2 路线引导功能，因此配件必须在判断何时向用户呈现路线引导数据的逻辑中使用 RouteGuidanceUpdate 消息的 RouteGuidanceState 和 SourceSupportsRouteGuidance 参数。

禁止配件将路线引导信息发送给外部来源，包括但不限于远程服务器。配件不得持久化存储路线引导信息，也不得将其用于向用户显示路线引导以及准备电动车充电之外的任何用途。

8.3 示例

8.3.1 普通路口示例

图 8-1（第 230 页）所描绘的路口元素将具有以下 RouteGuidanceManeuverInformation 参数：

  • ManeuverType：1
  • DrivingSide：0
  • JunctionType：0
  • JunctionElementExitAngle：-58
  • JunctionElementAngle：28
  • JunctionElementAngle：70

8.3.2 环岛路口示例

图 8-2（第 231 页）所描绘的路口元素将具有以下 RouteGuidanceManeuverInformation 参数：

  • ManeuverType：28
  • DrivingSide：0
  • JunctionType：1
  • JunctionElementAngle：-89
  • JunctionElementAngle：-54
  • JunctionElementAngle：-28
  • JunctionElementAngle：19
  • JunctionElementExitAngle：64

8.3.3 用法示例

  1. 配件使用一个或多个 RouteGuidanceDisplayComponent 进行识别。
  2. 配件发送 StartRouteGuidanceUpdates 消息。
  3. 设备开始生成 RouteGuidanceUpdate 消息。
    • 如果路线引导未激活：RouteGuidanceState 参数设为 NoRouteSet，等待路线引导开始。
    • 如果路线引导已激活：RouteGuidanceState 参数设为 Route Set、Loading、Locating、Rerouting 或 Proceed to Route。
  4. 设备发送携带初始路线引导机动动作的 RouteGuidanceManeuverInformation 消息，数量不超过配件可处理的最大机动动作数。RouteGuidanceState 设为 Active，路线引导处于激活状态。
  5. 设备发送携带初始车道引导信息列表的 LaneGuidanceInformation 消息，数量不超过配件指定的最大值。
  6. 随着时间和行驶里程推移，设备发送 RouteGuidanceUpdate、RouteGuidanceManeuverInformation 和 LaneGuidanceInformation 消息以更新信息。
    • 接近某个机动动作时，Maneuver 状态按 Continue → Initial → Prepare → Execute → Continue 转换。ManeuverType 参数指定机动动作类型（例如右转）。
    • 如果需要显示车道引导，LaneGuidanceCurrentIndex 参数被更新，PresentLaneGuidance 参数设为 TRUE，表示应显示车道引导。当不再需要显示车道引导时，PresentLaneGuidance 参数设为 FALSE。
    • 重复以上过程，直到路线引导结束。
  7. 如果用户行驶到达目的地，设备发送 RouteGuidanceState 设为 Arrived 的 RouteGuidanceUpdate 消息。
  8. 当路线引导结束——无论是因已到达目的地，还是用户选择结束路线引导——设备发送 RouteGuidanceState 设为 NoRouteSet 的 RouteGuidanceUpdate 消息。
