用 Canvas 手写一个协作白板渲染引擎

从脏矩形重绘到光标插值，聊聊我在 Verdant 里踩过的性能坑。

做协作白板最容易被低估的，不是实时同步，而是渲染。当画布上有了几百个图形、十几个人的光标在同时移动，浏览器很快就会用掉你所有的帧预算。下面是我在这个项目里逐步摸索出的一套做法。

一、不要全量重绘

最初我天真地每帧调用一次 clearRect 再画全部元素，结果 200 个图形就掉到了 20fps。真正的开关是脏矩形：只重绘发生变化的最小区域。

function invalidate(rect) {
  dirty.push(rect);
  scheduleFrame();
}

function render() {
  for (const r of dirty) ctx.clearRect(r.x, r.y, r.w, r.h);
  for (const item of visibleIn(dirty)) draw(item);
  dirty.length = 0;
}

二、光标要做插值

网络消息再频繁也有间隔，直接把远端光标「瞬移」过去会显得很卡。我们在收到坐标后做线性插值，让视觉保持连续：

流畅感往往不是来自更高的帧率，而是来自更可预测的运动。

用 requestAnimationFrame 在每帧里把光标位置朝目标值逼近一点，体感立刻顺滑起来。

三、分层画布

把静态图形与动态光标分到两张 Canvas 上：静态层很少重绘，动态层每帧轻量更新。这样既省 GPU，也让脏矩形逻辑更干净。

  • 底图 / 图形层：变化少，缓存离屏
  • 光标 / 选区层：每帧更新，独立合成
  • 网格层：用 CSS 背景平铺，完全不进 Canvas

小结

最终我们在百人同屏下稳住了 60fps。核心经验只有一句：把「画什么」和「什么时候画」彻底分开想，性能问题就解决了一大半。
