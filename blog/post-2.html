为什么我写了第三个静态站点生成器

Lumen 的诞生记：对「写作体验」的偏执，以及如何把构建时间压到 200ms 内。

市面上的静态站点生成器已经够多了。Hugo、Eleventy、Astro……我本不该再写一个。但当我真正每天用它写东西时，发现它们总在某个细微处让我皱眉：要么配置太长，要么中文排版敷衍，要么构建慢得让人失去即时反馈的快感。

写作体验是第一优先级

Lumen 的设计只有一个信条：让写作者忘记工具的存在。你写下 Markdown，它就该立刻变成一页好看的文章。

好的工具不让你感到它的存在，只让你感到自己写得更顺了。

把构建压到 200ms 以内

关键是增量构建：只重新处理改动的文件，其余从缓存读取。一个几十篇文章的站点，单次改动构建稳定在 200ms 内，几乎和保存文件同时完成。

// 监听文件变化，仅重建受影响的页面
watcher.on("change", (file) => {
  const affected = graph.dependentsOf(file);
  build(affected);   // 通常只有 1~3 个文件
});

为中文排版而生

标点挤压、合适的行距、首字下沉——这些在西方模板里常被忽略的细节，在 Lumen 里是默认行为。毕竟，中文网页值得被认真对待。

  • 自动标点挤压（，，。的间距修正）
  • 长文自动首字下沉
  • 代码块深色主题，与文艺底色不冲突

小结

写第三个生成器不是重复造轮子，而是把我对「写作这件事」的理解，固化进一个每天陪我工作的工具里。它现在有 2.1k Stars，但对我而言，最好的评价是：我自己一天都离不开它。
